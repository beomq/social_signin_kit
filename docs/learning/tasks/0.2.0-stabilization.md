# 0.2.0 안정화와 배포

## 요청과 승인

사용자는 남은 웹 안내, 텍스트 대비, 위젯 로고·포커스 API, 일반 비활성
로고 경계 수정을 요청했고 커밋·병합·새 버전 게시까지 명시적으로 승인했다.
사용자 직접 검증과 이해 확인은 아직 하지 않았다.

## 선택과 코드

- `lib/src/social_login_button.dart`: `SocialButton.custom`으로 이미지 자산
  외 위젯을 받는다. 기존 asset 생성자는 유지하며 공개 `logo` getter만
  nullable로 바뀌므로 0.2.0으로 올린다. 앱이 `FocusNode`를 소유한다.
- 같은 파일의 내부 버튼 상태는 로딩 중 내용의 상태·크기를 보존하고 입력을
  차단한다. 콜백은 지연하지 않고 빠른 탭 피드백만 잠시 유지한다.
- 일반 disabled는 전체 버튼을 하나로 50% 합성한다. 서로 같은 원본 배경을
  다르게 변형하지 않아 불투명 로고 경계가 나타나지 않는다. 처음부터 다른
  배경의 자산은 자동 보정하지 않는다. 최종 disabled 대비는 앱 배경에 따른다.
- `lib/src/social_login_provider.dart`: LINE·Naver·VK 문구를 `#111111`로
  변경한다. 배경·로고는 그대로이며 공식 흰색 문구와 다른 패키지 선택이다.
  활성 대비는 각각 8.37, 6.10 이상, 4.57이다. VK와 LINE도 대비를 유지하는
  공통 상태 효과를 사용한다.
- `landing/`: hosted `^0.2.0` 설치, 생성 JSON·에이전트 안내, 필수 로고 예제,
  코드 전용 게시 설명과 웹 팔레트를 맞춘다.

## 실행 근거

- Flutter 3.29.0·3.29.2 각각 패키지 147개, 예제 8개 테스트 통과.
- 두 버전 모두 루트·예제 analyze 통과, 예제 release web 빌드 성공.
- 기존 예제 CupertinoIcons 폰트 경고는 남아 있다. 앱 코드의 신규 실패는 없다.
- 실제 로고·Noto 글꼴을 사용한 Flutter 상태 캡처: 390·1440 폭, light·dark.
  활성·disabled·loading 상태에서 경계·크기·정렬을 직접 확인했다.
- 브라우저 선택기에서 LINE·Naver·VK 선택 후 글자색 `rgb(17, 17, 17)`과
  생성 JSON의 `publication: pub.dev`, `version: ^0.2.0` 확인.
- 설치·쇼케이스·제공자 안내의 390·1440 화면에서 가로 넘침 없음.
- publish dry-run의 첫 경고는 미커밋 파일뿐이었다. 게시 전 커밋 후 재검사한다.

## 직접 확인과 장애 확인 순서

예제의 로딩 스위치 또는 앱의 `isLoading`을 켜고 클릭·Enter 차단, 완료 후
복원을 확인한다. `SocialButton.custom`에 상태가 있는 로고를 넣어 상태가
유지되는지 확인한다. 문제가 생기면 설치 버전, 앱의 로딩 해제 경로,
로고 원본 배경·크기, 실제 앱 배경 순으로 확인한다. 이 작업은 소비 앱의
인증 로직이나 의존성을 바꾸지 않는다.
